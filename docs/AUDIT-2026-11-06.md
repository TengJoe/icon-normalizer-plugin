# 产出质量审计 2026-11-06

对 `~/.local/share/icons/DockNormalized` 中的**全部产出**做一次独立审计：用插件自己的 `analyze()` 逐个测量，检查占比、居中度与圆角形态是否与策略一致。

## 方法

- 样本：**625 个 PNG / 73 个图标 × 9 个尺寸**（16–512）。
- 占比：`core_bbox`（alpha > 200）对角线 / 画布，容差 `target ± deadband = 0.83 ± 0.02`（判定区间 0.805–0.855）。
- 居中：核心包围盒中心与画布中心的像素偏差，阈值 1px。
- 圆角：四角不透明度 `corner_alpha`，≥0.5 视为直角、<0.05 视为圆角，其余为抗锯齿过渡。

## 结果

| 检查 | 结果 |
| --- | --- |
| 占比超差 | **2 / 625**（均为小尺寸 1px 取整） |
| 中心偏差 > 1px | **0** |
| 圆角分布 | 直角 52 · 圆角 490 · 抗锯齿过渡 83 |

### 占比超差明细

| 尺寸 | 图标 | 实测 | 目标 | 说明 |
| --- | --- | --- | --- | --- |
| 16px | `onlyoffice-desktopeditors` | 0.750 | 0.83 | 12px vs 理想 13.3px，**差 1px** |
| 24px | `firefox` | 0.792 | 0.83 | 19px vs 理想 19.9px，**差 1px** |

两者都是**最小尺寸下的像素取整**：16px 画布上 1px 即 6.25%，任何非整数目标都不可避免地落在某一侧。视觉上不可分辨，**决定不作特殊处理**。

## 附带发现并修复的问题

首轮审计（634 个 PNG）发现 **9 个孤儿文件**：`local.deb.Installer.png` 九个尺寸仍是**旧策略 88%** 的产物，且清单中已无任何条目引用（图标名从 `local-deb-installer` 变为 `local.deb.Installer` 后旧文件残留）。

已于 1.1.27（后台 3.1.19）修复：每轮运行删除主题 `*/apps/` 下未被任何条目引用的 PNG，删除同样纳入事务。修复后复测：**磁盘 625 = 清单 625，孤儿 0**。

## 复现命令

```sh
# 占比 + 居中 + 圆角审计（需要仓库 backend 在 sys.path 上）
python3 - <<'PY'
import sys; sys.path.insert(0, "backend")
from pathlib import Path
from PIL import Image
from icon_normalizer.core.analyzer import analyze
theme = Path.home() / ".local/share/icons/DockNormalized"
for png in theme.glob("*/apps/*.png"):
    m = analyze(Image.open(png).convert("RGBA"))
    size = int(png.parents[1].name.split("x")[0])
    if abs(m.cx - size / 2) > 1 or abs(m.cy - size / 2) > 1:
        print("off-centre:", png, m.cx, m.cy)
PY
```
